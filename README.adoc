== Status

Chancel has *no code yet*. This repository currently holds only the scaffolding
it was minted with from the RSR template (`rust-cli` archetype): a placeholder
crate whose single function reports the package name and version, its tests,
CI workflows, and the machine-readable repository metadata. Nothing here yet
checks a Chapel program, gates a Chapel subset, or emits a proof obligation.

What is planned, and not yet built: a subset gate for Chapel programs and a
proof-obligation front end over the Canonry theory. The repository deed
(`chancel_chora.deed`) is the place where its identity, boundaries and
relationships are recorded; some of its fields are still `UNASSIGNED` and wait
for the owner.

== Working in this repository

[source,bash]
----
mise trust && mise install    # the toolchain pinned in mise.toml
mise exec -- just             # lists the phases (build, test, validate, audit, ...)
mise exec -- just validate    # structure and metadata checks
cargo test --locked           # the placeholder crate's tests
----

`mise exec --` puts the toolchain on `PATH` for that one command. Once mise is
activated in your shell, plain `just` works.

Run `just doctor` if something is missing; each failure carries a code explained
in link:docs/SETUP.adoc#troubleshooting[`docs/SETUP.adoc`].

== Governance badges

The *K9 conformance* badge in the row at the top is published after an eligible push to `main`, by
`.github/workflows/dogfood-gate.yml` to a generated *orphan* branch called
`governance-badges`, and read back through the shields endpoint.

[cols="1,3",options="header"]
|===
| Badge | What it means

| green `success`
| The K9 lane ran for that commit on `main` and passed.

| red `failure`
| The K9 lane ran for that commit on `main` and failed.

| grey `skipped`, `cancelled`, `unavailable`, `unknown`
| That commit produced *no trustworthy* K9 result. Grey is not "pending" and
  not a stale green: a skipped, cancelled or unavailable lane replaces an
  earlier green badge with grey.
|===

* `governance-badges` is *generated output*. It deliberately has *no common
  ancestor with `main`*, it has no pull request, and it must *never be merged*.
  Recent pushes to it are ordinary badge refreshes.
* A run that would publish the same bytes makes *no commit at all*.
* Nothing in the badge pipeline can turn a failing validation green: only a
  lane that ran and passed, with its artifact present, renders brightgreen.

The full operational contract - the exact state table, how API errors are
classified, how concurrent publications are serialised, and how to repair a bad
file - is in link:.github/workflows/README.adoc[`.github/workflows/README.adoc`].

== Repository map

The authoritative map is generated, so it cannot drift from the tree:
link:docs/architecture/REPOSITORY-MAP.adoc[docs/architecture/REPOSITORY-MAP.adoc]
(regenerate with `just repo-map`; CI fails if it is stale).

The short version:

[cols="1,3"]
|===
| Path | What lives there

| `README.adoc`, `CLAUDE.md` | Start here - humans and AI agents respectively.
| `src/`, `tests/`           | The code and its tests.
| `docs/`                    | Human documentation, including the full map above.
| `.machine_readable/`        | Manifests, contractiles and policies that tools read.
| `build/`, `Justfile`       | Every task runs through `just`; phases live in `build/just/`.
| `ci/`, `.github/`          | CI configuration; GitHub reads `.github/` and no other path.
|===
